Sensor Plugin Configuration Examples for Humanoid Simulation

Introduction

Sensors are crucial for humanoid robots to perceive their environment and maintain balance. Proper configuration of sensor plugins in Gazebo is essential for realistic simulation and effective robot behavior. This chapter provides comprehensive examples for configuring various types of sensors commonly used in humanoid robotics: LiDAR, cameras, IMU, and force/torque sensors.

LiDAR Sensor Configuration

LiDAR sensors provide 360-degree distance measurements that are essential for navigation, obstacle detection, and mapping in humanoid robots.

2D LiDAR Configuration

<!-- Hokuyo UTM-30LX equivalent 2D LiDAR -->
<gazebo reference="lidar_link">
  <sensor name="laser_sensor" type="ray">
    <always_on>true</always_on>
    <visualize>true</visualize>
    <update_rate>40</update_rate>
    <ray>
      <scan>
        <horizontal>
          <samples>720</samples>
          <resolution>1</resolution>
          <min_angle>-3.14159</min_angle>  <!-- -π radians -->
          <max_angle>3.14159</max_angle>    <!-- π radians -->
        </horizontal>
      </scan>
      <range>
        <min>0.1</min>
        <max>30.0</max>
        <resolution>0.01</resolution>
      </range>
    </ray>
    <plugin name="laser_controller" filename="libgazebo_ros_ray_sensor.so">
      <ros>
        <namespace>/humanoid_robot</namespace>
        <remapping>~/out:=scan</remapping>
      </ros>
      <output_type>sensor_msgs/LaserScan</output_type>
      <frame_name>lidar_link</frame_name>
    </plugin>
  </sensor>
</gazebo>

3D LiDAR Configuration (Velodyne-like)

<!-- VLP-16 equivalent 3D LiDAR -->
<gazebo reference="velodyne_link">
  <sensor name="velodyne_sensor" type="ray">
    <always_on>true</always_on>
    <visualize>false</visualize>
    <update_rate>10</update_rate>
    <ray>
      <scan>
        <horizontal>
          <samples>1800</samples>
          <resolution>1</resolution>
          <min_angle>-3.14159</min_angle>
          <max_angle>3.14159</max_angle>
        </horizontal>
        <vertical>
          <samples>16</samples>
          <resolution>1</resolution>
          <min_angle>-0.2618</min_angle>  <!-- -15 degrees -->
          <max_angle>0.2618</max_angle>    <!-- 15 degrees -->
        </vertical>
      </scan>
      <range>
        <min>0.2</min>
        <max>100.0</max>
        <resolution>0.01</resolution>
      </range>
    </ray>
    <plugin name="velodyne_controller" filename="libgazebo_ros_velodyne_gpu.so">
      <ros>
        <namespace>/humanoid_robot</namespace>
        <remapping>~/out:=points</remapping>
      </ros>
      <frame_name>velodyne_link</frame_name>
      <min_range>0.2</min_range>
      <max_range>100.0</max_range>
      <gaussian_noise>0.008</gaussian_noise>
    </plugin>
  </sensor>
</gazebo>

Camera Sensor Configuration

Cameras provide visual information for perception, navigation, and manipulation tasks in humanoid robots.

RGB Camera Configuration

<!-- Head-mounted RGB camera -->
<gazebo reference="camera_link">
  <sensor name="camera_sensor" type="camera">
    <always_on>true</always_on>
    <visualize>true</visualize>
    <update_rate>30</update_rate>
    <camera name="head_camera">
      <horizontal_fov>1.047</horizontal_fov>  <!-- 60 degrees -->
      <image>
        <width>640</width>
        <height>480</height>
        <format>R8G8B8</format>
      </image>
      <clip>
        <near>0.1</near>
        <far>100</far>
      </clip>
      <noise>
        <type>gaussian</type>
        <mean>0.0</mean>
        <stddev>0.007</stddev>
      </noise>
    </camera>
    <plugin name="camera_controller" filename="libgazebo_ros_camera.so">
      <ros>
        <namespace>/humanoid_robot</namespace>
        <remapping>image_raw:=image</remapping>
        <remapping>camera_info:=camera_info</remapping>
      </ros>
      <camera_name>head_camera</camera_name>
      <frame_name>camera_optical_frame</frame_name>
      <hack_baseline>0.07</hack_baseline>
      <distortion_k1>0.0</distortion_k1>
      <distortion_k2>0.0</distortion_k2>
      <distortion_k3>0.0</distortion_k3>
      <distortion_t1>0.0</distortion_t1>
      <distortion_t2>0.0</distortion_t2>
    </plugin>
  </sensor>
</gazebo>

Depth Camera Configuration (RealSense-like)

<!-- Intel RealSense-like depth camera -->
<gazebo reference="depth_camera_link">
  <sensor name="depth_camera_sensor" type="depth">
    <always_on>true</always_on>
    <visualize>true</visualize>
    <update_rate>30</update_rate>
    <camera name="depth_camera">
      <horizontal_fov>1.047</horizontal_fov>
      <image>
        <width>640</width>
        <height>480</height>
        <format>R8G8B8</format>
      </image>
      <clip>
        <near>0.1</near>
        <far>10</far>
      </clip>
    </camera>
    <plugin name="depth_camera_controller" filename="libgazebo_ros_openni_kinect.so">
      <ros>
        <namespace>/humanoid_robot</namespace>
        <remapping>image_raw:=rgb/image_raw</remapping>
        <remapping>depth/image_raw:=depth/image_raw</remapping>
        <remapping>depth/camera_info:=depth/camera_info</remapping>
        <remapping>rgb/camera_info:=rgb/camera_info</remapping>
      </ros>
      <camera_name>depth_camera</camera_name>
      <frame_name>depth_camera_optical_frame</frame_name>
      <baseline>0.1</baseline>
      <distortion_k1>0.0</distortion_k1>
      <distortion_k2>0.0</distortion_k2>
      <distortion_k3>0.0</distortion_k3>
      <distortion_t1>0.0</distortion_t1>
      <distortion_t2>0.0</distortion_t2>
      <point_cloud_cutoff>0.1</point_cloud_cutoff>
      <point_cloud_cutoff_max>5.0</point_cloud_cutoff_max>
    </plugin>
  </sensor>
</gazebo>

IMU Sensor Configuration

IMU sensors are critical for humanoid balance and orientation estimation.

High-Precision IMU Configuration

<!-- High-precision IMU for balance control -->
<gazebo reference="imu_link">
  <sensor name="imu_sensor" type="imu">
    <always_on>true</always_on>
    <update_rate>100</update_rate>
    <visualize>false</visualize>
    <imu>
      <angular_velocity>
        <x>
          <noise type="gaussian">
            <mean>0.0</mean>
            <stddev>2e-4</stddev>
            <bias_mean>0.0000075</bias_mean>
            <bias_stddev>0.0000008</bias_stddev>
          </noise>
        </x>
        <y>
          <noise type="gaussian">
            <mean>0.0</mean>
            <stddev>2e-4</stddev>
            <bias_mean>0.0000075</bias_mean>
            <bias_stddev>0.0000008</bias_stddev>
          </noise>
        </y>
        <z>
          <noise type="gaussian">
            <mean>0.0</mean>
            <stddev>2e-4</stddev>
            <bias_mean>0.0000075</bias_mean>
            <bias_stddev>0.0000008</bias_stddev>
          </noise>
        </z>
      </angular_velocity>
      <linear_acceleration>
        <x>
          <noise type="gaussian">
            <mean>0.0</mean>
            <stddev>1.7e-2</stddev>
            <bias_mean>0.1</bias_mean>
            <bias_stddev>0.001</bias_stddev>
          </noise>
        </x>
        <y>
          <noise type="gaussian">
            <mean>0.0</mean>
            <stddev>1.7e-2</stddev>
            <bias_mean>0.1</bias_mean>
            <bias_stddev>0.001</bias_stddev>
          </noise>
        </y>
        <z>
          <noise type="gaussian">
            <mean>0.0</mean>
            <stddev>1.7e-2</stddev>
            <bias_mean>0.1</bias_mean>
            <bias_stddev>0.001</bias_stddev>
          </noise>
        </z>
      </linear_acceleration>
    </imu>
    <plugin name="imu_controller" filename="libgazebo_ros_imu.so">
      <ros>
        <namespace>/humanoid_robot</namespace>
        <remapping>~/out:=imu/data</remapping>
      </ros>
      <frame_name>imu_link</frame_name>
      <body_name>imu_link</body_name>
      <update_rate>100</update_rate>
      <gaussian_noise>1.7e-2</gaussian_noise>
    </plugin>
  </sensor>
</gazebo>

Force/Torque Sensor Configuration

Force/torque sensors are essential for contact detection, manipulation, and balance control.

6-Axis Force/Torque Sensor

<!-- 6-axis force/torque sensor in the foot -->
<gazebo reference="left_foot_link">
  <sensor name="left_foot_ft_sensor" type="force_torque">
    <always_on>true</always_on>
    <update_rate>100</update_rate>
    <force_torque>
      <frame>child</frame>
      <measure_direction>child_to_parent</measure_direction>
    </force_torque>
    <plugin name="ft_sensor_plugin" filename="libgazebo_ros_ft_sensor.so">
      <ros>
        <namespace>/humanoid_robot</namespace>
        <remapping>~/out:=left_foot/ft_sensor</remapping>
      </ros>
      <frame_name>left_foot_link</frame_name>
      <body_name>left_foot_link</body_name>
      <update_rate>100</update_rate>
      <gaussian_noise>0.1</gaussian_noise>
    </plugin>
  </sensor>
</gazebo>

Multi-Sensor Integration Example

Complete Humanoid Sensor Configuration

Here's a complete example of a humanoid robot with multiple sensors:

<?xml version="1.0"?>
<robot xmlns:xacro="http://www.ros.org/wiki/xacro" name="humanoid_with_sensors">

  <!-- Include standard Gazebo plugins -->
  <gazebo>
    <plugin filename="libgazebo_ros2_control.so" name="gazebo_ros2_control">
      <parameters>$(find your_robot_description)/config/robot_control.yaml</parameters>
    </plugin>
  </gazebo>

  <!-- Base link -->
  <link name="base_link">
    <inertial>
      <mass value="10.0"/>
      <inertia ixx="0.1" ixy="0.0" ixz="0.0" iyy="0.1" iyz="0.0" izz="0.1"/>
    </inertial>
  </link>

  <!-- Torso with IMU -->
  <joint name="torso_joint" type="fixed">
    <parent link="base_link"/>
    <child link="torso_link"/>
    <origin xyz="0 0 0.5"/>
  </joint>

  <link name="torso_link">
    <inertial>
      <mass value="5.0"/>
      <inertia ixx="0.1" ixy="0.0" ixz="0.0" iyy="0.1" iyz="0.0" izz="0.1"/>
    </inertial>
  </link>

  <!-- IMU in torso -->
  <joint name="imu_joint" type="fixed">
    <parent link="torso_link"/>
    <child link="imu_link"/>
    <origin xyz="0 0 0.1" rpy="0 0 0"/>
  </joint>

  <link name="imu_link"/>

  <!-- Gazebo IMU plugin -->
  <gazebo reference="imu_link">
    <sensor name="torso_imu" type="imu">
      <always_on>true</always_on>
      <update_rate>200</update_rate>
      <imu>
        <angular_velocity>
          <x>
            <noise type="gaussian">
              <mean>0.0</mean>
              <stddev>2e-4</stddev>
            </noise>
          </x>
          <y>
            <noise type="gaussian">
              <mean>0.0</mean>
              <stddev>2e-4</stddev>
            </noise>
          </y>
          <z>
            <noise type="gaussian">
              <mean>0.0</mean>
              <stddev>2e-4</stddev>
            </noise>
          </z>
        </angular_velocity>
        <linear_acceleration>
          <x>
            <noise type="gaussian">
              <mean>0.0</mean>
              <stddev>1.7e-2</stddev>
            </noise>
          </x>
          <y>
            <noise type="gaussian">
              <mean>0.0</mean>
              <stddev>1.7e-2</stddev>
            </noise>
          </y>
          <z>
            <noise type="gaussian">
              <mean>0.0</mean>
              <stddev>1.7e-2</stddev>
            </noise>
          </z>
        </linear_acceleration>
      </imu>
    </sensor>
  </gazebo>

  <!-- Head with camera -->
  <joint name="head_joint" type="revolute">
    <parent link="torso_link"/>
    <child link="head_link"/>
    <origin xyz="0 0 0.3"/>
    <axis xyz="0 1 0"/>
    <limit lower="-0.5" upper="0.5" effort="10" velocity="1"/>
  </joint>

  <link name="head_link">
    <inertial>
      <mass value="1.0"/>
      <inertia ixx="0.01" ixy="0.0" ixz="0.0" iyy="0.01" iyz="0.0" izz="0.01"/>
    </inertial>
  </link>

  <!-- Camera in head -->
  <joint name="camera_joint" type="fixed">
    <parent link="head_link"/>
    <child link="camera_link"/>
    <origin xyz="0.1 0 0" rpy="0 0 0"/>
  </joint>

  <link name="camera_link"/>

  <!-- Gazebo camera plugin -->
  <gazebo reference="camera_link">
    <sensor name="head_camera" type="camera">
      <always_on>true</always_on>
      <update_rate>30</update_rate>
      <camera name="head_camera">
        <horizontal_fov>1.047</horizontal_fov>
        <image>
          <width>640</width>
          <height>480</height>
          <format>R8G8B8</format>
        </image>
        <clip>
          <near>0.1</near>
          <far>100</far>
        </clip>
      </camera>
    </sensor>
  </gazebo>

  <!-- LiDAR on head -->
  <joint name="lidar_joint" type="fixed">
    <parent link="head_link"/>
    <child link="lidar_link"/>
    <origin xyz="0.15 0 0.05" rpy="0 0 0"/>
  </joint>

  <link name="lidar_link"/>

  <!-- Gazebo LiDAR plugin -->
  <gazebo reference="lidar_link">
    <sensor name="head_lidar" type="ray">
      <always_on>true</always_on>
      <visualize>false</visualize>
      <update_rate>40</update_rate>
      <ray>
        <scan>
          <horizontal>
            <samples>720</samples>
            <resolution>1</resolution>
            <min_angle>-3.14159</min_angle>
            <max_angle>3.14159</max_angle>
          </horizontal>
        </scan>
        <range>
          <min>0.1</min>
          <max>30.0</max>
          <resolution>0.01</resolution>
        </range>
      </ray>
    </sensor>
  </gazebo>

  <!-- Left foot with force/torque sensor -->
  <joint name="left_foot_joint" type="fixed">
    <parent link="left_ankle_link"/>
    <child link="left_foot_link"/>
    <origin xyz="0 0 -0.05"/>
  </joint>

  <link name="left_foot_link">
    <inertial>
      <mass value="0.5"/>
      <inertia ixx="0.001" ixy="0.0" ixz="0.0" iyy="0.001" iyz="0.0" izz="0.001"/>
    </inertial>
  </link>

  <!-- Force/torque sensor in foot -->
  <gazebo reference="left_foot_link">
    <sensor name="left_foot_ft" type="force_torque">
      <always_on>true</always_on>
      <update_rate>100</update_rate>
      <force_torque>
        <frame>child</frame>
        <measure_direction>child_to_parent</measure_direction>
      </force_torque>
    </sensor>
  </gazebo>

</robot>

Sensor Fusion Configuration

Robot State Publisher with Multiple Sensors

Configure robot_state_publisher to handle multiple sensor frames:

# config/sensor_fusion.yaml
robot_state_publisher:
  ros__parameters:
    use_sim_time: true
    publish_frequency: 50.0
    # Frame configuration for all sensor links
    frame_prefix: ""
    # Additional parameters for sensor fusion
    use_tf_static: true
    ignore_timestamp: false

# Extended sensor configuration for fusion
imu_filter:
  ros__parameters:
    use_sim_time: true
    stateless: false
    use_mag: false
    publish_tf: false
    world_frame: "enu"  # or "ned"

    orientation_stddev: 0.001
    angular_velocity_stddev: 0.01
    linear_acceleration_stddev: 0.1

Physics Parameters for Sensor Accuracy

Adjust physics parameters for accurate sensor simulation:

<physics type="ode">
  <max_step_size>0.001</max_step_size>  <!-- 1ms for sensor accuracy -->
  <real_time_factor>1.0</real_time_factor>
  <real_time_update_rate>1000</real_time_update_rate>
  <ode>
    <solver>
      <type>quick</type>
      <iters>100</iters>
      <sor>1.3</sor>
    </solver>
    <constraints>
      <cfm>0.0</cfm>
      <erp>0.2</erp>
      <contact_max_correcting_vel>100.0</contact_max_correcting_vel>
      <contact_surface_layer>0.001</contact_surface_layer>
    </constraints>
  </ode>
</physics>

Troubleshooting Sensor Issues

Common Problems and Solutions

1. Sensor Data Not Publishing

  • Check sensor plugin loading in Gazebo
  • Verify topic names and namespaces
  • Ensure proper frame_id configuration
  • Check TF tree completeness

2. High CPU Usage with Multiple Sensors

  • Reduce sensor update rates where possible
  • Disable visualization for non-critical sensors
  • Use simpler sensor models for performance
  • Consider sensor multiplexing for high-frequency data

3. Inaccurate Sensor Readings

  • Verify sensor noise parameters
  • Check coordinate frame orientations
  • Validate physics parameters
  • Ensure proper sensor mounting positions

Diagnostic Tools

Sensor Status Check

# Check if sensor topics are being published
ros2 topic list | grep sensor

# Monitor sensor data
ros2 topic echo /humanoid_robot/imu/data
ros2 topic echo /humanoid_robot/scan
ros2 topic echo /humanoid_robot/camera/image_raw

TF Tree Verification

# Check TF tree for sensor frames
ros2 run tf2_tools view_frames
ros2 run tf2_ros tf2_echo base_link imu_link

Best Practices for Sensor Configuration

1. Realistic Noise Modeling

  • Include appropriate noise models based on real sensors
  • Use realistic bias and drift parameters
  • Consider environmental factors in noise models

2. Proper Frame Conventions

  • Follow ROS coordinate frame conventions
  • Use optical frames for cameras
  • Maintain consistent orientation across sensors

3. Resource Management

  • Balance sensor fidelity with performance
  • Use appropriate update rates for each sensor type
  • Consider the computational load of sensor processing

4. Calibration Considerations

  • Account for sensor mounting offsets
  • Include extrinsic calibration parameters
  • Consider thermal and environmental effects
