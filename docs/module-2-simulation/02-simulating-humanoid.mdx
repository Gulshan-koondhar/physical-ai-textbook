# Simulating Humanoid Robots in Gazebo

## Introduction

Simulating humanoid robots in Gazebo requires careful consideration of physics, control systems, and sensor integration. Unlike simpler wheeled robots, humanoid robots have complex kinematics, many degrees of freedom, and require sophisticated control algorithms to maintain balance and execute tasks. This chapter covers the essential techniques for creating realistic and stable humanoid robot simulations in Gazebo.

## Understanding Humanoid Simulation Challenges

### Balance and Stability

Humanoid robots face unique challenges in simulation:

1. **Center of Mass Management**: The robot must maintain its center of mass within its support polygon
2. **Dynamic Balance**: Unlike static structures, humanoid robots must actively balance during movement
3. **Contact Dynamics**: Foot-ground interaction is critical for stable locomotion
4. **Control Frequency**: High-frequency control is needed for stable balance

### Physics Complexity

Humanoid simulation involves complex physics interactions:

- Multiple simultaneous contacts (feet, hands during manipulation)
- Complex joint constraints
- High degrees of freedom requiring precise control
- Sensitivity to small parameter changes

## Balance Control in Simulation

### Center of Mass Considerations

For stable balance in simulation:

```python
# Example: Balance controller (simplified)
import rclpy
from rclpy.node import Node
from sensor_msgs.msg import Imu, JointState
from geometry_msgs.msg import Vector3
import numpy as np

class BalanceController(Node):
    def __init__(self):
        super().__init__('balance_controller')

        # Subscriptions
        self.imu_sub = self.create_subscription(
            Imu, '/imu/data', self.imu_callback, 10)

        self.joint_state_sub = self.create_subscription(
            JointState, '/joint_states', self.joint_state_callback, 10)

        # Publishers
        self.joint_cmd_pub = self.create_publisher(
            JointState, '/joint_commands', 10)

        # Timer for control loop (1000 Hz for fast response)
        self.control_timer = self.create_timer(0.001, self.balance_control)

        # Internal state
        self.current_imu = Imu()
        self.current_joints = JointState()
        self.balance_active = True

        # Balance control parameters
        self.roll_pid = {'kp': 10.0, 'ki': 0.1, 'kd': 0.5}
        self.pitch_pid = {'kp': 10.0, 'ki': 0.1, 'kd': 0.5}

    def imu_callback(self, msg):
        """Handle IMU data for balance feedback"""
        self.current_imu = msg

    def joint_state_callback(self, msg):
        """Handle current joint states"""
        self.current_joints = msg

    def balance_control(self):
        """Main balance control algorithm"""
        if not self.balance_active:
            return

        # Get current orientation from IMU
        orientation = self.current_imu.orientation
        roll, pitch, yaw = self.quaternion_to_rpy(orientation)

        # Calculate balance errors
        roll_error = 0.0 - roll  # Target roll = 0
        pitch_error = 0.0 - pitch  # Target pitch = 0

        # Simple PID control for balance correction
        roll_correction = (self.roll_pid['kp'] * roll_error +
                          self.roll_pid['ki'] * self.integrated_roll_error +
                          self.roll_pid['kd'] * self.derived_roll_error)

        pitch_correction = (self.pitch_pid['kp'] * pitch_error +
                           self.pitch_pid['ki'] * self.integrated_pitch_error +
                           self.pitch_pid['kd'] * self.derived_pitch_error)

        # Apply corrections to ankle joints
        self.apply_balance_correction(roll_correction, pitch_correction)

    def quaternion_to_rpy(self, quaternion):
        """Convert quaternion to roll-pitch-yaw"""
        import math
        q = quaternion
        sinr_cosp = 2 * (q.w * q.x + q.y * q.z)
        cosr_cosp = 1 - 2 * (q.x * q.x + q.y * q.y)
        roll = math.atan2(sinr_cosp, cosr_cosp)

        sinp = 2 * (q.w * q.y - q.z * q.x)
        pitch = math.asin(sinp)

        siny_cosp = 2 * (q.w * q.z + q.x * q.y)
        cosy_cosp = 1 - 2 * (q.y * q.y + q.z * q.z)
        yaw = math.atan2(siny_cosp, cosy_cosp)

        return roll, pitch, yaw

    def apply_balance_correction(self, roll_correction, pitch_correction):
        """Apply balance corrections to ankle joints"""
        cmd_msg = JointState()
        cmd_msg.header.stamp = self.get_clock().now().to_msg()

        # Add balance corrections to ankle joints
        cmd_msg.name = ['left_ankle_pitch', 'left_ankle_roll',
                       'right_ankle_pitch', 'right_ankle_roll']
        cmd_msg.position = [pitch_correction, roll_correction,
                           pitch_correction, roll_correction]

        self.joint_cmd_pub.publish(cmd_msg)

def main(args=None):
    rclpy.init(args=args)
    balance_controller = BalanceController()

    try:
        rclpy.spin(balance_controller)
    except KeyboardInterrupt:
        pass
    finally:
        balance_controller.destroy_node()
        rclpy.shutdown()

if __name__ == '__main__':
    main()
```

## Walking Pattern Generation

### Inverse Kinematics for Walking

Implement walking patterns with inverse kinematics:

```python
# Example: Simple walking pattern generator
import numpy as np
import math

class WalkingPatternGenerator:
    def __init__(self):
        # Walking parameters
        self.step_height = 0.1  # Height of foot lift
        self.step_length = 0.3  # Distance per step
        self.step_duration = 1.0  # Time per step
        self.zmp_margin = 0.05  # Zero Moment Point safety margin

    def generate_step_trajectory(self, time, leg_side, step_phase):
        """
        Generate foot trajectory for walking
        leg_side: 'left' or 'right'
        step_phase: 0.0 to 1.0 (0 = start of step, 1 = end of step)
        """
        # Calculate foot position based on step phase
        x = self.step_length * step_phase
        y = 0.0  # Lateral position (depends on gait)

        # Foot lift trajectory (cycloid or similar)
        if step_phase < 0.5:
            # Rising phase
            z = self.step_height * (1 - math.cos(math.pi * step_phase * 2)) / 2
        else:
            # Falling phase
            z = self.step_height * (1 - math.cos(math.pi * (step_phase * 2 - 1))) / 2

        # Adjust for leg side
        if leg_side == 'left':
            y = 0.1  # Left leg offset
        else:
            y = -0.1  # Right leg offset

        return x, y, z

    def generate_com_trajectory(self, time):
        """Generate Center of Mass trajectory for balance"""
        # Simple CoM trajectory for walking
        com_x = self.step_length * time / self.step_duration
        com_y = 0.0  # Keep CoM centered laterally
        com_z = 0.8  # Maintain constant height

        return com_x, com_y, com_z
```

## Debugging Humanoid Simulation

### Common Issues and Solutions

#### 1. Robot Falls Over Immediately
- Check mass distribution and center of mass
- Verify joint limits and initial positions
- Check ground contact parameters
- Ensure proper controller initialization

#### 2. Oscillatory Behavior
- Reduce controller gains
- Check sensor noise levels
- Verify physics parameters (CFM, ERP)
- Check timing and update rates

#### 3. Joint Limit Violations
- Verify joint limits in URDF
- Check controller position bounds
- Ensure trajectory generators respect limits
- Add soft limits in controllers

#### 4. High CPU Usage
- Simplify collision geometries
- Reduce physics iterations
- Lower sensor update rates
- Use efficient controllers
