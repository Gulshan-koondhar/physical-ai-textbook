# ROS 2 Bag Recording and Foxglove Studio Integration

## Introduction

Data recording and analysis are critical for developing and debugging humanoid robots. ROS 2 provides the `ros2 bag` tool for recording and replaying data, while Foxglove Studio offers advanced visualization and analysis capabilities. Together, these tools enable comprehensive debugging, performance analysis, and system validation for complex humanoid systems.

In this chapter, you'll learn how to effectively use ROS 2 bag for data recording and how to integrate with Foxglove Studio for advanced visualization and analysis.

## Understanding ROS 2 Bag

### What is ROS 2 Bag?

ROS 2 Bag is the data recording and playback system for ROS 2. It allows you to:
- Record messages from any ROS 2 topic
- Replay recorded data for testing and debugging
- Extract specific information from recorded data
- Convert between different storage formats

### Basic ros2 bag Commands

#### Recording Data

To record all topics:
```bash
ros2 bag record -a
```

To record specific topics:
```bash
ros2 bag record /joint_states /tf /imu/data /camera/image_raw
```

To record with a custom prefix:
```bash
ros2 bag record -o my_humanoid_session /joint_states /tf
```

#### Advanced Recording Options

Record with compression:
```bash
ros2 bag record -o compressed_session --compression-mode file --compression-format zstd /joint_states
```

Record with specific QoS settings:
```bash
ros2 bag record --qos-profile-sensor-data /camera/image_raw
```

#### Playback Data

Basic playback:
```bash
ros2 bag play my_recording_2023_12_07-14_30_00
```

Playback at different speeds:
```bash
ros2 bag play my_recording --rate 0.5    # Half speed
ros2 bag play my_recording --rate 2.0    # Double speed
```

Loop playback:
```bash
ros2 bag play my_recording --loop
```

## Recording Humanoid Robot Data

### Essential Topics for Humanoid Robots

When recording data for humanoid robot analysis, consider recording these key topics:

#### Joint Information
```bash
ros2 bag record /joint_states /joint_commands
```

#### Sensor Data
```bash
ros2 bag record /imu/data /tf /tf_static /camera/image_raw /scan
```

#### Control and Planning
```bash
ros2 bag record /cmd_vel /move_base_simple/goal /plan
```

#### System Status
```bash
ros2 bag record /robot_status /diagnostics /rosout
```

### Example Recording Session

For a complete humanoid walking demonstration:
```bash
ros2 bag record -o humanoid_walk_test \
  /joint_states \
  /tf \
  /imu/data \
  /cmd_vel \
  /robot_status \
  /foot_contact_states
```

### Selective Recording

To avoid overwhelming storage requirements, use selective recording:

```bash
# Record only high-priority topics at full rate
ros2 bag record -o humanoid_demo_high_priority \
  --include-topics "joint_states|imu/data|robot_status"

# Record everything but exclude high-bandwidth topics
ros2 bag record -o humanoid_demo_filtered \
  --exclude-topics "camera/image_raw|/points"
```

## Analyzing Recorded Data

### Basic Analysis Tools

#### Information Command
Get information about a recorded bag:
```bash
ros2 bag info humanoid_walk_test
```

This shows:
- Duration of recording
- Topics included
- Message counts
- Storage options used

#### Slice Command
Extract a specific time range:
```bash
ros2 bag slice -o walk_step_1 --start 10.0 --duration 2.0 humanoid_walk_test
```

#### Filter Command
Filter topics in an existing bag:
```bash
ros2 bag filter -o joints_only --topics /joint_states humanoid_walk_test
```

### Custom Analysis Scripts

Create Python scripts to analyze recorded data:

```python
# analyze_joint_data.py
import rosbag2_py
from rclpy.serialization import deserialize_message
from rosidl_runtime_py.utilities import get_message
import matplotlib.pyplot as plt
import numpy as np

def analyze_joint_states(bag_path):
    """Analyze joint state data from a ROS 2 bag"""

    # Create storage options
    storage_options = rosbag2_py.StorageOptions(
        uri=bag_path,
        storage_id='sqlite3'
    )

    # Create converter options
    converter_options = rosbag2_py.ConverterOptions(
        input_serialization_format='cdr',
        output_serialization_format='cdr'
    )

    # Create a sequential reader
    reader = rosbag2_py.SequentialReader()
    reader.open(storage_options, converter_options)

    # Get all topics and types
    topic_types = reader.get_all_topics_and_types()

    # Find joint_states topic
    joint_states_topic = None
    for topic_type in topic_types:
        if topic_type.name == '/joint_states':
            joint_states_topic = topic_type
            break

    if joint_states_topic is None:
        print("joint_states topic not found")
        return

    # Set filter for joint states
    storage_filter = rosbag2_py.StorageFilter(topics=['/joint_states'])
    reader.set_filter(storage_filter)

    # Store joint positions over time
    timestamps = []
    joint_positions = {}

    while reader.has_next():
        (topic_name, msg_data, timestamp) = reader.read_next()

        # Deserialize message
        msg_type = get_message(joint_states_topic.type)
        msg = deserialize_message(msg_data, msg_type)

        # Store data
        timestamps.append(timestamp / 1e9)  # Convert to seconds

        for i, joint_name in enumerate(msg.name):
            if joint_name not in joint_positions:
                joint_positions[joint_name] = []
            joint_positions[joint_name].append(msg.position[i])

    # Plot results
    fig, ax = plt.subplots(figsize=(12, 8))

    for joint_name, positions in joint_positions.items():
        if len(positions) > 0:
            ax.plot(timestamps[:len(positions)], positions, label=joint_name, alpha=0.7)

    ax.set_xlabel('Time (s)')
    ax.set_ylabel('Joint Position (rad)')
    ax.set_title('Joint Position Over Time')
    ax.legend(bbox_to_anchor=(1.05, 1), loc='upper left')
    ax.grid(True)

    plt.tight_layout()
    plt.show()

    return joint_positions

# Example usage:
# joint_data = analyze_joint_states('humanoid_walk_test')
```

## Foxglove Studio Integration

### What is Foxglove Studio?

Foxglove Studio is a visualization and debugging tool for robotics that provides:
- Web-based interface for multi-device access
- Flexible layout system for custom dashboards
- Advanced plotting and analysis tools
- Support for multiple robotics frameworks (ROS 1, ROS 2, Protobuf, JSON)
- Real-time and playback data visualization
- Collaboration features

### Setting up Foxglove Studio with ROS 2

#### Installation

Foxglove Studio can be used in two ways:
1. **Desktop Application**: Download from foxglove.dev
2. **Web Application**: Use studio.foxglove.dev

#### Connecting to ROS 2

Foxglove Studio connects to ROS 2 through the Foxglove Bridge:

```bash
# Install foxglove-bridge
sudo apt install ros-humble-foxglove-bridge

# Launch the bridge
ros2 launch foxglove_bridge foxglove_bridge_launch.xml
```

## Data Analysis Workflows

### Pre-Mission Analysis

Before running humanoid experiments:
1. **Baseline Data Collection**: Record normal operation
2. **Calibration Verification**: Ensure sensors are properly calibrated
3. **Range of Motion Testing**: Verify joint limits and ranges

### Real-Time Monitoring

During humanoid operation:
1. **Live Data Visualization**: Monitor key parameters
2. **Anomaly Detection**: Identify unusual patterns
3. **Performance Metrics**: Track execution times, resource usage

### Post-Mission Analysis

After humanoid experiments:
1. **Data Playback**: Replay and analyze complete sessions
2. **Statistical Analysis**: Calculate means, variances, extremes
3. **Comparative Analysis**: Compare with baseline or previous runs
4. **Failure Analysis**: Investigate error conditions

## Performance Considerations

### Storage Management

For humanoid robots with many sensors:
- Plan storage requirements in advance
- Use appropriate compression settings
- Implement data rotation strategies
- Consider cloud storage for large datasets

### Real-Time Performance

When recording and visualizing:
- Balance data fidelity with performance
- Use appropriate sampling rates
- Consider the impact of recording on system performance
- Implement selective recording for high-bandwidth topics

Use consistent topic names for easy analysis:
