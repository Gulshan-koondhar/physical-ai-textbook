# Troubleshooting

This appendix provides solutions to common issues encountered when working with the Physical AI & Humanoid Robotics textbook content.

## ROS 2 Issues

### Command Not Found
**Problem**: `command not found` errors when running ROS 2 commands
**Solution**: Ensure you've sourced the ROS 2 setup file:
```bash
source /opt/ros/humble/setup.bash
```
Or add it to your `.bashrc`:
```bash
echo "source /opt/ros/humble/setup.bash" >> ~/.bashrc
source ~/.bashrc
```

### Network Configuration
**Problem**: Nodes on different machines cannot communicate
**Solution**: Set the same ROS_DOMAIN_ID on all machines:
```bash
export ROS_DOMAIN_ID=42
```

### Package Not Found
**Problem**: `Package not found` when building workspace
**Solution**: Ensure dependencies are installed:
```bash
sudo apt update
rosdep update
rosdep install --from-paths src --ignore-src -r -y
```

## Simulation Issues

### Gazebo Not Starting
**Problem**: Gazebo fails to start or crashes
**Solution**:
1. Check if GPU drivers are properly installed
2. Try running with software rendering:
```bash
export LIBGL_ALWAYS_SOFTWARE=1
```

### Physics Simulation Problems
**Problem**: Robot falls through ground or exhibits unstable behavior
**Solution**: Adjust physics parameters in SDF/URDF files:
- Increase damping values
- Check collision meshes
- Verify mass and inertia properties

## AI Model Issues

### CUDA Memory Errors
**Problem**: "CUDA out of memory" errors
**Solution**:
1. Reduce batch size in model inference
2. Use model quantization
3. Clear GPU memory: `nvidia-smi --gpu-reset -i 0`

### Model Loading Failures
**Problem**: AI models fail to load
**Solution**: Verify model files are complete and compatible with installed frameworks

## Hardware Deployment Issues

### Jetson Power Management
**Problem**: Jetson throttles performance during AI inference
**Solution**: Set to MAXN mode:
```bash
sudo nvpmodel -m 0
sudo jetson_clocks
```

### Communication Failures
**Problem**: Host PC cannot communicate with humanoid robot
**Solution**:
1. Check network connectivity
2. Verify ROS master URI configuration
3. Check firewall settings

## Docusaurus/Website Issues

### Local Server Won't Start
**Problem**: `npm start` fails to start development server
**Solution**:
1. Clear cache: `npm run clear`
2. Reinstall dependencies: `npm install`
3. Check Node.js version (must be >=18.0)

### Build Failures
**Problem**: `npm run build` fails
**Solution**:
1. Check for syntax errors in MDX files
2. Verify all referenced files exist
3. Increase Node.js memory limit: `export NODE_OPTIONS="--max-old-space-size=4096"`

## Performance Optimization

### Slow Simulation
**Problem**: Gazebo simulation runs slowly
**Solution**:
1. Reduce physics update rate in world file
2. Simplify collision meshes
3. Reduce number of sensors in simulation

### High CPU/GPU Usage
**Problem**: Excessive resource consumption
**Solution**:
1. Optimize model complexity
2. Use appropriate data types
3. Implement proper throttling in nodes

## Common Python Issues

### Import Errors
**Problem**: `ModuleNotFoundError` or `ImportError`
**Solution**:
1. Ensure ROS 2 environment is sourced
2. Check PYTHONPATH
3. Verify package.xml and setup.py files

### Virtual Environment
**Problem**: ROS 2 conflicts with virtual environments
**Solution**: Source ROS 2 setup before activating virtual environment, or use separate terminals.

## Debugging Strategies

### Enable Debug Logging
```bash
export RCUTILS_LOGGING_SEVERITY_THRESHOLD=DEBUG
```

### Use rqt Tools
```bash
ros2 run rqt_graph rqt_graph  # Visualize node connections
ros2 run rqt_console rqt_console  # View logs
```

### Monitor System Resources
```bash
# Monitor ROS 2 topics
ros2 topic list
ros2 topic echo /topic_name

# Monitor system resources
htop
nvidia-smi
```

## Reporting Issues

When reporting issues, include:
1. System configuration (OS, hardware, software versions)
2. Exact error messages
3. Steps to reproduce
4. Expected vs. actual behavior
